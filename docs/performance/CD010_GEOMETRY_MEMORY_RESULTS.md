- H20/B1→B4，backward host中位数7.281→5.470秒，forward host4.730→4.222秒；future等待仅0.271→0.223秒。因此观察到的收益不能只解释为少等CPU几何。B4仍有较大的前向/反向耗时，而loader约3ms、optimizer约9ms，不支持优先继续增加数据worker。
- L20/B1→B3，backward host1.695→1.477秒，但forward host1.938→2.138秒，future等待0.073→0.130秒，部分收益被抵消。数据等待只有约1–4ms/更新。显存容量允许B3运行，但没有带来吞吐提升。
- H20/B8单图的forward host升至8.818秒，串行几何host约6.008秒；其反向5.169秒略低于B4双图，整体仍更慢。L20/B4单图也出现forward host约3.954秒，失去重叠后大batch优势不足以弥补总耗时。

这些是已有host区间，含同步影响，不是孤立CUDA kernel时间；后台job可与GPU工作重叠，不能与前向/反向时间相加。不同microbatch的BN分组与损失数值行为也会变化，并可能改变预测驱动的几何工作量。未追加trace，不能据此确定具体kernel是算力、带宽还是调用粒度受限。

## 5. 选择与日志

H20/E5的性能候选选择为microbatch4/depth2；本轮具体组合为B4A6、有效batch24。L20/E3建议保留microbatch1/depth2；本轮对应B1A12、有效batch12。有效24/12只是同机扫描条件，**不是已确定的正式训练有效batch**。历史有效batch4的吞吐不能直接作为这轮加速基线；最终训练仍须保持已约定的总有效样本预算，不能照搬旧更新次数。

每台机器的独立测试根目录以 `$BENCH_ROOT` 表示，输出分别在 `H20-E5-batch-scan/` 和 `L20-E3-batch-scan/`：

- `plan.json`记录固定矩阵、原始配置路径、实际命令、分配资源与无限额策略。
- `summary.json`、`summary.md`保留所有完成/OOM候选、完整排名和阶段统计。
- 每档 `train.json`、`performance.json`、`execution.json`、`console.log`；OOM原始堆栈不删除。
- 每档 `run/attempts/<attempt>/updates.jsonl`、`events.jsonl`、runtime身份及训练器原生生成的checkpoint文件；没有额外备份/恢复流程。
- 外层 `benchmark.log`、`scan-exit-code`记录扫描结束。两机扫描均已结束，完整训练未启动。

若后续决定优化接触头，可另行按方案评估pose chunk；本轮没有执行该扩展。当前结论来自各档一次短测，没有以复跑或额外检查补充证据。
