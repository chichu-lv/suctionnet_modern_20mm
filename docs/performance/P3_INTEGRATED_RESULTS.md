2026-11-13。**H20/E5 的 65,536 + split + 原生接触查询组合通过完整四帧配对；L20/E3 只有保留 16,384 的 split + 原生查询组合通过。原计划的 L20 65,536 组合未通过，不能据此续训。** 本文是技术测试记录，不代表六组训练完成，也不把数值配对通过等同于生产吞吐收益。

## 配对范围与结果

每组读取自己的正常暂停 checkpoint，使用该 checkpoint 的相同四帧及增强种子，在同一次真实骨干输出上分别执行基线与候选后缀，再将两组实际 cotangent 回传到同一骨干图。检查包括输入、目标、离散选择、固定输入几何字节、模型输出、loss、后缀梯度、骨干 VJP、四帧累积梯度、buffer、RNG 和 sampler 状态。**所有配对均为零 optimizer 更新，未计入正式训练预算。**

保留 B1A4、原 AMP、原 checkpoint 的 GradScaler scale、原硬件 profile、2 mm 网络体素、完整观测、512 候选及损失定义。浮点门槛始终为 **atol = 2e-4、rtol = 2e-3**；离散与固定输入几何字节检查未放宽。`no_instance_voxel_heads=false`。

## 原生几何字节差异与修复

H20 首次失败的四帧 core 描述量分别有 183 / 136 / 233 / 189 个 float32 位模式不同，但数值差异全部为零：参考为 `+0.0`，原生实现为 `-0.0`。其他区域字节相同，所有梯度比较也相同。L20 同样存在独立的 core 正负零差异。

根因是精确锚点偏移为零时，原生三项点积从第一项乘积开始相加，可能保留负零；参考 NumPy contraction 从正零开始累加。修复将局部坐标投影和观测法向点积统一从 `+0.0` 开始，保持三个乘积及非零加法顺序、FP64、禁用 fast-math 和 FMA contraction。过滤、FPS、计数、随机 roll 和比较门槛均未改变。回归检查使用字节比较，覆盖带符号轴与随机 roll，而非仅用忽略正负零差别的数值相等。

该修复已发布于 [`f4f7f0d6de0bd3bd27107d8be09885fed700e48b`](https://github.com/chichu-lv/suctionnet_modern_20mm/commit/f4f7f0d6de0bd3bd27107d8be09885fed700e48b)。两份修复后配对报告记录的执行身份是基于 `759e0ac198ff18747063186cf0779850caed086d` 应用修复后的 worktree `0d44b123d9b15d312b64b05aafe992c3e454f7f6c1805eb94e4b070915b2cea1`；不将其改写为后来发布的 Git HEAD。原生源文件 SHA256 均为 `5497af34edf3424f004b71c9dc73c0ed6cf62e167733263ea7d7d8158b6360c5`，各设备原生二进制身份分别保存在报告中。

## L20 的 64k 梯度门槛为什么失败

原 L20 组合的 148 项失败包括：4 个 core 几何 SHA；逐帧后缀梯度张量 11 / 10 / 10 / 10 项；第三帧骨干 VJP 57 项；四帧累积后缀 9 项及骨干 37 项。失败证据完整保留，没有用后来的通过报告替换。

原组合的 loss 和离散输出完全相同，所有梯度有限，但 dense fusion、axis、q0 的 Linear 梯度逐帧有 7,398 / 9,672 / 9,767 / 11,884 个元素超过原门槛。最大绝对差达到 16，**这是 checkpoint scale = 262,144 下的 scaled 梯度差异**，不是未缩放的优化器梯度差异。H20 的源 scale 为 131,072。比较始终使用原 scale 与原容差，没有除以 scale 后重新判定通过。

L20 第三帧只有 335 个骨干边界 cotangent 元素不同，最大绝对差为 `6.103515625e-5`，通过了边界自身的门槛；同一骨干图上的真实 VJP 仍出现 57 个失败张量。其余三帧 cotangent 完全相同。q0 输出逐帧有 15 / 9 / 17 / 0 个元素不同，输出比较仍通过。局部输出或 loss 接近不足以代替完整梯度门槛。

源码及隔离结果支持 chunk 大小造成的有限精度差异：16k → 64k 改变 GEMM 行维度、权重梯度归约长度和分块贡献的舍入/累加边界；保持 16k 后，split 与修复后的原生查询一起通过同四帧检查。没有证据支持把此次失败归咎于模型层、监督或随机种子被更换，也没有据此认定 split 本身失败。

尚无经过验证、同时执行实际 64k GEMM、复现原 16k FP16 舍入并保留预期收益的小改动。64k 前向配合自定义 16k 反向还需处理已不同的前向中间量及 checkpoint 重算；禁用 AMP、改为 FP32 梯度、改变 scale 或放宽容差均未采用。这不证明所有未来 64k 实现都不可能，只说明**当前 64k 候选不能通过这次严格续训门槛**。

H20/E5 已将第 8,330 步的正常暂停 checkpoint 迁移到已发布修复 `f4f7f0d`，恢复正式训练。原硬件 profile、57,600 次成功更新 / 230,400 有效帧预算、B1A4、CPU8、loader workers2 均未改变。正常 receipt、identity 与日志核验的 17 项检查全部通过；首步为 8,331，optimizer attempt、采样器、AMP scale=131,072 和学习率沿原状态接续。优化器状态保留依赖现有身份迁移与严格恢复流程，本轮没有另建张量审计或恢复框架。
