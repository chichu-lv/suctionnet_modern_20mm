# 实验与评价实施方案

> 本文件规定实验，不提供未发生的结果。当前目标是先得到可用于少量自有场景微调的公开数据预训练权重。已有训练数据通过 [adapter](LEGACY_DATA_ADJUSTMENT.md) 直接复用；实验不要求重新制作整套标签。模型定义见 [MODEL.md](MODEL.md)，训练预算见 [TRAINING.md](TRAINING.md)。

## 1. 本轮要验证的问题

1. GT-B 中加入 Wrench 后，是否改善同一 R20 最终姿态质量？
2. 实例整体几何和吸盘局部几何是否各自提供收益，二者是否互补？
3. S/W/C 联合辅助监督是否值得保留？
4. 公开数据权重经过少量目标场景微调后，是否改善独立目标场景表现？

前三个问题用公开数据离线实验回答，第四个使用已有目标数据。公开数据预训练效果不等于真实业务成功率；真实成功数据也不自动提供未执行候选的反事实成功标签。

## 2. 六组独立预训练配置

| ID | q0 与 q 监督 | 实例特征融合 I | 物理分区精炼 R | S/W/C 辅助 |
|---|---|---|---|---|
| E0 | GT-A | 关 | 关 | 关 |
| E1 | GT-B | 关 | 关 | 关 |
| E2 | GT-B | 开 | 关 | 关 |
| E3 | GT-B | 关 | 开 | 关 |
| E4 | GT-B | 开 | 开 | 关 |
| E5 | GT-B | 开 | 开 | 开 |

每组独立从相同初始化规则训练；不是把 E0 训练后接 E1、再一路接 E5。共同使用同一主干、输入、轴头、实例均衡候选采样、GT-A 高低分采样规则、视角序列、增强规则、优化器更新次数和后处理。没有 R 时仍保留最终 q 头，输入区域块置零。没有 I 仍保留实例采样与区域 same-instance 标记，所以只能称“没有实例特征融合”，不能称“完全没有实例信息”。

| 比较 | 可回答的问题 |
|---|---|
| E1−E0 | 加 Wrench 后，对同一最终 R20 任务的影响 |
| E2−E1、E4−E3 | 无/有 R 时，I 的贡献 |
| E3−E1、E4−E2 | 无/有 I 时，R 的贡献 |
| E5−E4 | 联合辅助监督的贡献 |
| 最终模型−E1 | 主要设计带来的效果和计算代价 |

E1–E4 是 I×R 的 2×2 设计。E5 只证明联合辅助的效果，不拆成“S、W、C 各自有效”的结论。当前不增加同容量普通邻域聚合对照，因此不宣称已证明环形结构优于所有其他结构。

首轮统一 seed=42。默认优先 E4；E5 在验证主指标有实用增益时才替代。可事先把 1 个百分点设为工程选择的参考幅度，但它不是统计显著性标准。若差距很小且不稳定，选更简单的配置。只有确实需要确认小优势时，给 E1 和最终模型补 seed=43、44，不要求六组全做三次。

## 3. 公开数据划分与选模

| 集合 | 场景 | 视角 | 用途 |
|---|---|---|---|
| train | 官方 0000–0099 中 `scene_id%10!=9`，共 90 场景 | 每场景每 epoch 64 帧，无放回 | 40 epoch 预训练 |
| validation | 0009、0019、…、0099，共 10 场景 | 固定 `0,8,…,248`，每场景 32 帧 | 模型与 checkpoint 选择 |
| test Seen | 0100–0129 | 每场景 256 帧 | 锁定方案后一次报告 |
| test Similar | 0130–0159 | 同上 | 同上 |
| test Novel | 0160–0189 | 同上 | 同上 |

同一场景的相邻视角不得分到 train/val 两侧。默认 realsense；若用户已制作的另一相机数据要用，单独注明，不把两相机同场景当作独立留出场景。

主选模指标：`instance_Top1_Q20_at_0_4`；并列用 AP-R20，再并列保留更早 checkpoint。验证每 4 epoch 一次和训练结束时一次。固定标签的 Seal 归一化来自已有 `config_frozen.json`，不因内部 90/10 划分重新拟合；这意味着 validation 是场景划分的开发集，不应称“完全独立物体标注的测试集”。

六组先用同一 GT 实例 mask 控制变量。选定后，只对 E1 与最终模型，在相同验证帧上额外使用现有前置模型预测 mask，观察实际感知管线的差异；不用为此训练新的分割系统。

## 4. R20 评价器：必须按实际输出姿态计算

### 4.1 评价分数

对模型实际输出的接触点 `p` 和外法向 `n`：

```text
S(p,n) = clip((Seal_raw20(p,n)-lo)/(hi-lo), 0, 1)
W(p,n) = 1-min(1, ||tau-(tau·n)n||_2/(k*r*pi))
tau = (center-p) × (mass*gravity)
C(p,n) = 1-collision_current(p,n)
Q20(p,n) = S(p,n)*W(p,n)*C(p,n)
```

`lo/hi`、半径、质量、k、重力、桌面、障碍采样分辨率、包络和 self-height 阈值全部取**产生这份数据时的冻结配置**。默认质量 1 kg、center 为该实例全部 Seal 候选位置的均值、k=15.6、重力加速度 9.8；不使用网络可见中心替代评价中心，不默认改成额外测量的真实质心。

源码核对显示旧 `dc4ad6b` 与新 `b2680fb` 的 Wrench 均为切向力矩 L2；这里不是要将用户旧数据从别的范数迁移到 L2。与旧 SuctionNet API 的两个切向分量绝对值取 max 的写法不同，因此称 **AP-R20 项目协议**。仅把官方 API 半径改成 .02，不能自动对齐本项目的归一化、范数、碰撞包络和 NMS。出处见 [REFERENCES.md](REFERENCES.md)。

### 4.2 原始 Seal 的计算契约

`suction20/eval_r20.py` 已实现任意 `(p,n)` 的原式Seal评价，并通过32个冻结候选的一致性核对；见 [验证记录](../MODEL_VALIDATION.md)。实现使用实际生产脚本的单候选数学过程，不改用近似Seal，也不重新发布上游完整脚本。

1. 用 GT 物体姿态把预测 `(p_cam,n_cam)` 变换到目标物体坐标系。在物体坐标系按原 Seal 的切平面约定构造 72 扇区，避免仅因用相机系重建切平面而改变扇区起点。普通非退化轴使用原 `new_y=(n_y,-n_x,0)`、`new_x=new_y×n`；轴恰与 z 平行时给一个确定性正交基即可，不开展额外极端姿态实验。
2. 使用制作原 Seal 的同一物体稠密点集/poisson 输入，不用网络 2 mm 体素点云替代。环带条件沿用 `r-0.1*r < rho < r+0.1*r`，r=.020，72 个角区间边界沿用上游规则。
3. 每扇区取 z 最大值形成实际环顶点；某扇区无点，则原 Seal 分数为 0。相邻顶点含最后到第一个闭环。
4. `deform` 为理想相邻弦长 / 实际三维相邻边长的最小值。`fit=exp(-100000*mean((z_sector-mean(z_sector))**2))`，`Seal_raw=fit*deform`。此处是对原脚本计算的等价表达，不改成自由倾斜平面拟合。
5. 原 Seal 局部碰撞 `any(rho<r and z>.005)` 单独返回。场景碰撞函数必须以这个 `self_collision` 为初值，再检查已有三段包络。不要只查场景包络后漏掉原 self-collision 项。

已有 `wrench_scores_dual`、`collision_mask_for_instance`、`scene_table_cloud`、场景姿态与 dense 加载函数可直接复用。Seal 和 Wrench 的完整 GT 几何只在离线评价使用，不传给推理模型。

## 5. 指标精确定义

### 5.1 AP-R20

每个场景视角：根据模型分数排序，采用 [MODEL.md](MODEL.md#9-推理去重和执行) 共同的 NMS，每输入实例最多 10 个、全场景最多 50 个。对阈值 `t∈{.2,.4,.6,.8}`：

```text
P@k(t) = sum(i=1..min(k,K)) [Q20_i>=t] / k,  k=1..50
AP_R20_view = mean_t mean_k P@k(t)
AP_R20_scene = mean_views AP_R20_view
AP_R20_split = mean_scenes AP_R20_scene
```

不足 k 个预测时分母仍是 k。无候选视角为 0。先场景内平均、再场景间平均。三个官方测试 split 分开报；可附它们的均值，但不能掩盖 Novel 单列结果。这个 AP 是多个 P@k 的平均，不是检测 PR 曲线面积。

预测点本轮始终来自观测点，评价所有权通过原 NPZ 的 `source_indices→instance_id_gt` 对应关系读取；也可调用现有 `resolve_instance_ids`。官方原始 label PNG 保存的是类别，不能直接把其像素值当场景实例行号。调用评价器时 `gt_instance_row=instance_id_gt-1`，背景0对应-1。背景候选计失败；**不用预测 ID 决定它属于哪个真实物体**。预测 mask 把一个物体拆成多 ID 时仍按真实归属统计。同样，`gt_valid=False` 不是删掉输出候选的理由：任意姿态评价可以直接判断该输出。

### 5.2 每实例 Top-1 与诊断指标

| 指标 | 定义/解释 |
|---|---|
| `instance_Top1_Q20_at_0_4` | 固定当前视角中有观测点的 GT 目标实例；在每输入实例 NMS/10个截断之后、全场景 Top-50 之前，按真实归属从所有提议中取最高分，Q20≥.4 计成功，无提议计失败。帧内实例平均，再视角/场景平均 |
| Top-1 collision rate | 上述 Top-1 中碰撞比例；同时报告无候选率，不能把无候选解释为低碰撞收益 |
| proposal coverage@512 | 在拥有 `gt_valid & gt_B>=.4` 可观测点的 GT 实例中，512提议是否至少包含一个这样的点；是缓存标签诊断，不是最终姿态成功率 |
| normal angle median/P90 | 对 `axis_valid` 的原候选轴计算 `acos(clamp(dot,-1,1))`，单位度；不是对 PCA 目标算角度 |
| masked q error | 有标签观测点/种子上的 MAE、SmoothL1；同时记录GT覆盖率；不能替代未过滤输出的完整评价 |
| latency / memory | batch1，同硬件；预热20帧后固定100帧，CUDA计时同步；报告中位数/P95与峰值显存 |

延迟至少拆为观测预处理/体素化、主干、候选+局部分组+头、NMS；前置检测分割另列。包括真实CPU/GPU传输，不只计算主干 kernel 时间。离线 GT 评价时间不计入推理延迟。

法向影响可用同一 checkpoint 做一次推理诊断：固定提议点，将预测轴替换为观测轴并重新评价，观察最终质量是否改善；这是推理诊断，不增加一组独立训练。它不能把标签轴当部署可用输入。

## 6. 少量目标场景：按已有监督类型评价

具体划分和 200+800 步训练见 [FINETUNING.md](FINETUNING.md)。同一场景、连续录制/session、同一实际尝试的多个视角必须在同一分组中；先固定 train/val/test manifest，再启动微调。不要求为六个公开消融各做一次目标域微调。

### 6.1 已有同语义物理标签：`dense_proxy`

比较选中公开模型的 **zero-shot** 与同架构 **fine-tuned**。目标标签若确实能按相同 R20 规则评价任意 `(p,n)`，使用相同每实例 Top-1、AP-R20、碰撞和延迟。归一化沿用源预训练，不逐目标场景重新标度。

若只有既有固定点/姿态上的分数，没有完整几何评价能力，则只能比较这些已有姿态上的 masked q 误差和排序诊断，明确测试范围；不为凑 AP 而近邻取缓存分数，也不要求额外制作全套 CAD 数据。与源标签语义不同的目标评分不能直接覆盖 `gt_B`，需在目标数据契约中明确其含义。

### 6.2 已有实机尝试结果：`attempt_success`

每条记录是实际 `(scene,p_exec,n_exec,outcome)`；使用 `score_at_pose` 在同一 executed pose 上评分。未执行点的结果未知，不能作为失败。比较：

| 配置 | 训练 | 可报告的目标结果 |
|---|---|---|
| source zero-shot q | 不用目标标签 | q 与既有执行成功的 AUROC/PR-AUC 排序关联；不报告 q 的成功概率校准 |
| 冻结表示的 task head | 同一目标训练集，仅训练新成功头 | 成功分类/概率指标；用于判断表示是否已够用 |
| target fine-tuned | 同样标签，新头+解冻 decoder | 与上一行比较，衡量少量特征适配是否值得 |

分类报告 AUROC（测试集包含两类时）、PR-AUC/average precision（注明不是 AP-R20）、二元交叉熵、Brier；样本少时给实际正负数量。Brier 与 BCE 仅适用于经过目标成功监督的 task head，不把物理 q 当成功概率。类别不足时报告实际构成和可计算指标即可，不为了补齐指标扩建采集任务。

这些是已有行为策略选择的执行样本上的评价。它们不能直接证明新策略选择未执行候选的 Top-1 成功率；完整策略提升由后续正常业务执行验证。source zero-shot 与 task head 的采样提议仍相同 q0；本轮不另训练 proposal 网络去猜未执行点结果。

### 6.3 没有目标监督时

只有无标注 RGB-D 时，先做公开模型 zero-shot 推理与可视化，不声称已完成有监督微调。用户以后已有的少量评分或真实尝试即可进入上述对应模式；当前不安排新的复杂半监督/自训练体系作为前置工作。

## 7. 可选残差排序实验

本节 residual uncertainty 训练工具尚未交付；保留为可选实验规格，不是公开预训练或目标微调的前置条件。

只在公开主模型锁定后做：冻结同一候选和同一姿态，对比 q 与 `q-lambda*sigma`，lambda 为 0/.25/.5；按同一验证主指标选。可附 5 个 sigma 分箱的 RMSE，检查误差尺度是否有用。不因一个错误剔除曲线好看就声称概率校准，更不能将共享小头分歧等同认知不确定性。

没有验证收益就关闭。微调之后默认 lambda=0；若目标数据本来足以重拟合同语义物理残差，再做小规模同样验证，不把此项变成目标微调的额外必修实验。

## 8. 进入实机阶段时的正常工况比较

这不是当前公开预训练或旧数据调整的前置条件。若后续要用一轮可控试验验证微调价值，比较**同一选中架构的公开 pretrained-only 与 target fine-tuned**，每种 100 次，共 200 次即可作为首轮工程证据。公开 E0–E5 已回答架构问题，不在真机上重复整张矩阵。

使用 20 个普通混堆模板，每个方法每模板 5 次，模板内交替方法，尝试前按同一规则复原/重置。固定相机、分割、吸盘、控制速度、下压和真空动作；测试模板不参与目标微调。

成功定义为抓起并完成运输和放置；中途掉落、无可执行候选均计一次任务失败并记录原因。记录成功次数/总次数、每模板结果、漏气/脱落/碰撞或无法执行/未知原因。给出二项区间时注明重复模板的相关性，主要比较应同时展示模板内差异；不以 100 次/方法证明很小百分比差异稳定存在。也可以使用已有正常业务试运行记录，不必为形式补满一个新的特殊工况套件。

## 9. 结果记录与执行顺序

每次 run 保存：模型配置、adapter 路径、已有标签来源与冻结配置、数据划分 manifest、seed、代码提交、实际 optimizer steps、选中 checkpoint 和指标 JSON。大数据、权重和运行日志留在训练存储，不提交 Git。

建议结果表字段：

```text
run_id, config_id, seed, phase, label_source, input_mask_source,
checkpoint_step, split, target_supervision_mode,
instance_Top1_Q20_at_0_4, AP_R20, collision_rate, no_candidate_rate,
proposal_coverage, normal_median_deg, normal_p90_deg,
latency_median_ms, latency_p95_ms, peak_memory_mb
```

目标实际成功模式另存 `n_success,n_failure,AUROC,PR_AUC,BCE,Brier`，不把它们填进物理质量字段。

旧缓存 adapter、E1–E5 所需模块及有界训练/评价链路已实现。后续实验顺序为：E0–E5 正式同预算预训练对比 → 选定公开权重 → 独立目标场景 zero-shot / 少样本微调对比 → 进入业务时再做执行验证。首轮不要求新做材质专项、全物体质量质心标定、时序跟踪或大规模超参数网格。
